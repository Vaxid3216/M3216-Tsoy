## 4. Возникшие проблемы и их решение

| Проблема | Причина | Решение |
|---|---|---|
| Скрипт запуска выводил только `Python` и завершался | Терминал VS Code был открыт до установки Python, в `PATH` осталась заглушка Microsoft Store | Перезагрузка `PATH` в терминале |
| «Запуск PostgreSQL… команда завершилась с кодом 1» | Порт 5432 занят ранее установленной службой Windows `postgresql-x64-18` | В `.env` задан `POSTGRES_PORT=5433`; системная служба не затронута |
| `TelegramNetworkError: Cannot connect to host api.telegram.org:443` (таймаут) | Прямой доступ к Telegram API заблокирован | В `.env` задан `TELEGRAM_PROXY_URL` на локальный SOCKS5-прокси VPN-клиента (127.0.0.1) |

Файл `.env` исключён из Git (`.gitignore`), токен и пароли в репозиторий не попадают.

## 5. Использование AI-инструментов

Использовался **Claude Code** (Anthropic) — для чтения методички, диагностики
ошибок запуска и проверки окружения.

**Пример исправленного предложения AI.** Ассистент проверил доступность
`api.telegram.org` через `curl` и, получив ответ, предложил запускать бота без
прокси. При запуске бот упал с таймаутом соединения: проверка через `curl`
оказалась нерепрезентативной, поскольку проходила через VPN-клиент, а
Python-приложение обращалось к Telegram напрямую. Решение исправлено — прокси
указан явно, после чего бот запустился. Вывод: ответ ассистента подтверждается
только фактическим запуском приложения.
